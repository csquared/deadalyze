# Second round: the engine, and the threshold applied (2026-10-08)

The first round (`2026-10-08-first-round.md`) ended with a recommendation:
relabel bar 1 on the cross-checker's vote at 0.7 agreement instead of 0.9,
and run Beat This on `mps`. Both were host constants, duplicated in Go and
Swift. This round moved the recipe behind one engine
(`../engine-protocol.md`) and made both a setting
(`../../settings/dance4x4.json`), then ran the same two sets through it.

## What ran

`bin/engine` 0.1.0 (Rust; legs `beatnet-dbn-v15`, `beat-this-v2`,
`madmom-key-cnn-2018`, `dc7f-1` in Python), recipe `deadca7-v2`, against
the installed `ml-v0.1.2` runtime with the legs from this checkout,
device `auto` (`mps` here). `grideval -fresh` through the client, in
batches of 64. About 5 s a track; the first round's harness took 20.

## The failure set

The 191 SAYLESS1 tracks the first round's engine got wrong
(`build/grideval-fresh-sayless1-failures.json` → `build/grideval-engine-sayless1-failures.json`).

| outcome                                         | tracks |
|-------------------------------------------------|-------:|
| pass now                                        | 67     |
| of which: the vote relabel at 0.7               | 58     |
| of which: the half-beat shift                   | 2      |
| of which: other (origin landed within tolerance)| 7      |
| still off                                       | 123    |
| error (the WAV ffmpeg refuses)                  | 1      |

The first round counted 30 fixes for the threshold from the vote the old
run recorded. The engine fixes 58 with it: the vote is recorded on the
same run that is scored now, and the batch leg's vote differs from the
one-track leg's on some tracks (the run-to-run drift the first round
measured, which the vote inherits).

## The pass sample

The 150 tracks of the first round's pass sample
(`build/grideval-fresh-sayless1-passes.json` → `build/grideval-engine-sayless1-passes.json`):
149 pass. The one that does not is `11A - 120 - Cafe De Anatolia …`, at
0.48 beats both before and now with no relabel and agreement 0.63: the
same half-beat flipper the first round's rerun found, not the threshold.

**No regression from the recipe change; 67 of 191 failures fixed.**

## The engine against what it replaced

- On the WIRED fixture (`fixtures/grideval/refs.json`) the engine's grid
  is deadcatalog's Go engine's to the millisecond (117.02 BPM, first
  downbeat 117 ms), on `cpu` and on `mps`, with the same identity hash.
- The waveform renderer is byte for byte the Go one on a synthetic signal
  and on the fixture MP3 (0 bytes differ across the seven kinds and the
  streamed frames); `waveeval` scores the same numbers to three decimals.
- `cmd/engineconf` passes on the development setup and on a locally built
  layout-3 bundle (`ml-v0.3.0-dev`, 1.68 GB).

## Open

- The 123 still off are the first round's other classes (origin fractions,
  half-beat origins, tempo), untouched by this round; items 2 to 5 of the
  first round's list stand.
- The drift: the vote itself drifts between runs, so a threshold tuned on
  one run is slightly off on the next. Pinning the legs' nondeterminism
  (item 2) comes before tuning anything further.
- The one WAV: a `soundfile` fallback in the legs (item 4).
